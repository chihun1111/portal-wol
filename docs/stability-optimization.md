# 성능 및 기존 기능 안정화

기준 커밋: `c796053da33bdbe41ae9880d97629ee31c034cc2`

작업 브랜치: `fix/optimize-stabilize-20261116`

검증일: 2026-11-16

## 변경 목적

기존 WOL, 현재 OS 기준 종료·재부팅, Ubuntu 선택 부팅, 타겟 관리, 상태 조회, 로그, 언어·테마 기능의 호출 방식은 유지하면서 실패 상황과 동시 요청을 보강했다. 새로운 전원 기능을 활성화하거나 실제 장비 설정을 변경하지 않았다.

## 검증 결과

환경: Python 3.12.14, Node.js 24.22.1. GitHub Actions는 프로젝트 Docker와 같은 Node.js 20, Python 3.12를 사용한다.

| 검증 | 결과 |
| --- | --- |
| 기준 커밋 Python 테스트 | 49개 통과 |
| 변경 후 `python -m pytest -q` | 129개 통과 |
| `npm test` | 13개 통과 |
| `npm run lint` | 경고·오류 없음 |
| TypeScript 검사 및 `npm run build` | 성공, 6개 정적 페이지 생성 |
| `scripts/build_frontend.sh --skip-install` | 성공, `app/static` 갱신 |
| `bash -n scripts/build_frontend.sh` | 통과 |
| FastAPI TestClient 정적 자산 점검 | `/wol` 자산 11개, `/settings` 자산 10개 모두 200 응답 |

주요 회귀 테스트는 느린 상태/전원 호출 중 서버 응답, 전원/편집 충돌, 취소와 BootNext 전환의 경쟁, 취소된 스레드가 종료되기 전 재실행 차단, 연결 종료, 타겟 파일 보존, 동시 CRUD, 실제 ARP 출력 형식, 로그 손상·정리 실패, 동시 로그 추가, 폴링 중첩·취소·타임아웃, 저장소 오류 및 초기 언어 렌더링을 검증한다.

Python 테스트의 1개 경고는 기존 Starlette 버전이 사용하는 AnyIO `BlockingPortal` 별칭의 폐기 예정 안내다. 테스트 실패는 없다. 실행 환경의 소켓 제한 때문에 Chromium 브라우저 자동화는 시작하지 못했다. Docker 실행과 Windows PowerShell 스크립트 실행도 이 환경에서 수행하지 않았다.

## 로그 조회 벤치마크

`scripts/benchmark_logs.py`는 기준 커밋의 로그 모듈과 변경 후 모듈을 같은 합성 파일로 실행한다. 실제 운영 로그를 읽거나 변경하지 않는다. 전체 Git 이력에 기준 커밋이 있어야 한다.

조건: 로그 50,000건, 최신 100건 조회, 보존 기간 정리 비활성화, `tracemalloc` 계측. 반환 결과는 동일했다.

| 항목 | 기존 | 변경 후 |
| --- | ---: | ---: |
| Python 최대 할당 메모리 | 37.764 MiB | 0.145 MiB |
| 계측 상태 실행 시간 | 9.020초 | 2.881초 |

이 샘플에서 최대 할당 메모리는 약 99.6% 감소했다. 시간은 메모리 계측과 실행 환경 부하가 포함된 단일 측정이며 운영 응답 시간의 보장이 아니다. 조회는 전체 파일을 한 번 읽지만 유지하는 레코드 수는 조회 제한에 비례한다. 조회 중 새 이벤트 추가는 레코드 파싱이 끝나기를 기다리지 않는다.

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
python scripts/benchmark_logs.py
cd web
npm ci --no-audit --no-fund
npm test
npm run lint
npm run build
```

## 운영에서 확인할 범위

- 현재와 같이 **단일 Uvicorn worker**로 실행한다. 프로세스 내 예약과 파일 잠금을 사용하므로 여러 worker/컨테이너가 같은 타겟을 제어하는 구성은 지원하지 않는다.
- 성공한 취소는 이후 BootNext/재부팅 단계 진행을 막는다. 취소 시 이미 진행 중인 WOL/SSH 호출은 완료될 수 있고, 해당 스레드가 끝날 때까지 타겟 예약을 유지한다.
- 단일 파일 bind mount의 직접 쓰기 경로는 전원 차단 시 원자성을 보장하지 않는다. 타겟 설정 백업을 유지한다. 잘못된 파일은 자동 초기화하지 않으며 수정 전까지 API가 503을 반환한다.
- 장비별 WOL 수신, SSH 인증, Windows BootNext, OS 전환은 모두 모의 처리했다. 실제 LAN·Tailscale·장비에서의 검증은 운영 적용 단계에서 수행해야 한다. 이번 작업에서 실제 장비 명령이나 운영 배포를 실행하지 않았다.
- 동일 오리진 운영 빌드의 `NEXT_PUBLIC_API_BASE` 기본값은 빈 문자열이다. 별도의 Next.js 개발 서버를 사용하는 경우에만 개발용 API 주소를 지정한다.
